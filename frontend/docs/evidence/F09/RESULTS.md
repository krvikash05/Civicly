- Current operational plan is selected by investigation.current_plan_id; a stale checkpoint budget pause does not override later approved/completed operations. Recovery uncertainty still takes priority. Completion, verified cause, component verification and final outcome are distinct.

Category changes clear an incompatible selected case. Lists remain bounded20investigations/60distinctincidentreads; errors are displayed rather than manufacturing a category or absence.

Work orders are scoped to returned plans, and native task IDs are resolved through authoritative task_bindings to show proper action names/targets. No unrelated orders are displayed when there is no current plan.
- Evidence modal displays the existing typed findings, observation dates, methods, values, source/field operator/reviewer. Review status does not become a claim of case resolution. Original statements/codes remain accessible.
- Plain status/action/department/role labels across evidence, work, plans, monitoring and updates. Removed unsupported claims that all supported evidence is physically verified, contradiction necessarily comes from a field inspection, CONTROLLED means no recurrence, empty history means first occurrence, or every nonclosing outcome means monitoring is currently continuing. Proposed synthetic procedures remain proposed reference material. Graph narrative distinguishes persisted path references from proven causal/model influence.
- Read errors use actual ApiError codes, not substring guesses that every409is a prerequisite or that unavailable services are reindexing. Failed optional memory/procedure/outcome reads are shown, not silently treated as successful empty data.
- Approval submission no longer guesses OP-DRAIN-LEAD or local taskIDs when authoritative bindings/uniqueeligibleoperators are missing. Original component request key retained across retries; uncertain response blocks resubmission in that component for operator review. This task did not submit/approve/create any work; the browser journey used reads only. Server remains authority.
- Role navigation says Roles & permissions and explains permissions without changing the signed-in role. Technical role/account IDs are in an explicit disclosure. New execution-origin text spans the status block width for legibility.
