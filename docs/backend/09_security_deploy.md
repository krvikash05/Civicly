# Local runtime, authorization, reliability and operational diagnostics

## Developer environment
- Python 3.12+ with `pyproject.toml` and lockfile, pytest/httpx/Pydantic, official `falkordb` Python client; LangGraph and official FalkorDBSaver via `langchain-falkordb[langgraph]` only after compatibility smoke; Python MCP SDK + Node official MCP server; GraphRAG SDK compatible pinned version; Docker Compose.
- FalkorDB Docker image: pin specific tested tag or digest **after runtime verification** (do not use `latest` in final lock); map internal 6379 and developer Browser port 3000, mount persistent volume path according to image docs and verify persistence by container recreation.
- API on localhost:8000, agent worker separate local process/container, official graph MCP internal e.g. port 8080 and custom MCP internal port distinct; no public database port outside development. Operator CLI entrypoint `python -m civicly_cli` or installed `civicly` executable (define in pyproject).
- `env.example` documents `FALKORDB_HOST`, `FALKORDB_PORT`, credentials if used, `FALKORDB_GRAPH`, `FALKORDB_DOC_GRAPH`, `MCP_FALKORDB_URL`, `MCP_CIVICLY_URL`, `MCP_API_KEY`, `MODEL_PROVIDER`, `MODEL_ID`, `OPENAI_API_KEY` (optional provider), `DEMO_MODE`, `DEMO_SEED`, `AUTH_SECRET`, `EVENT_WORKER_ID`, `DOCUMENT_DIR`, `SIMULATION_CLOCK`; never commit real secrets.
- `make` or task runner targets `setup`, `up`, `health`, `migrate`, `seed`, `demo-reset`, `test-unit`, `test-graph`, `test-mcp`, `test-agent`, `test-e2e`, `test-all`, `logs`, `down`.

## Demo security model
Seed demo local-only accounts with roles `ANALYST`, `DEPARTMENT_LEAD`, `APPROVER`, `ADMIN`; signed short-lived sessions or demo JWT configured with secure env secret, logout/revocation for session mode. Roles validated by server, per-department checks for work updates. Strictly demo, not enterprise identity management. No arbitrary requester identity fields are trusted. Simulated work always tagged as such.

## Attacks and defenses
| Threat | Enforcement |
|---|---|
| LLM or document tries to run arbitrary Cypher | Read-only broker allowlist, templates, restricted MCP exposure, parameterization; tests |
| Tool description spoofing | runtime tools/list allowlisted by server identity + tool name/declared schema/hash |
| API tries unauthorized approval | route RBAC + actor binding + plan version + hash + audit |
| Repeat request produces duplicate orders | idempotency key and persistent result + payload hash |
| Fault between DB mutation and event delivery | persisted event/outbox + reconciliation + failure injection |
| Agent misrepresents inspection as verified | Observation origin and signed simulated actor; hypothesis cannot mark verified absent finding |
| Private source includes prompt injection | sanitize/store as untrusted evidence, no tool/system policy changes |
| Expose sensitive values in log/SSE | PII/secret redaction and least-privilege fields |
| Overbroad graph visualization | bounded subgraph with server-side access filtering |
| Agent infinite tool loop | limits per run, timeouts, explicit human escalation |
| Concurrent approval changes plan | revision/hash compare and fail-closed |

## Observability
Structured JSON log fields: request_id, investigation_id, actor/role, task_id, plan_version, agent_run_id, tool execution_id, graph_revision, event_id, trace_id, latency_ms, status, simulated. `GET /health/live` and `/health/ready` checks FalkorDB, MCP, checkpoint adapter and durable event access. Metrics: actual tool count/latency, graph query count, invalid tool calls, schema validation failures, case state, unresolved events, token cost *if provider reports it*, approval stale errors. Do not invent KPIs.

Source repo, README setup, Cypher query catalog with explainability, `demo-reset`, scenario playbooks, `.env.example`, Docker Compose, sample CLI transcripts generated by real test runs, tests/results, architectural ADRs, video walkthrough script and statement of AI assistance.
